## 2. 数据表 `sys_operation_log`

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED 自增 | 否 | 日志 ID |
| `user_id` | BIGINT UNSIGNED | 是 | 操作人 ID；未登录或身份未接入时为 `NULL`，外键指向 `sys_user.id` |
| `operation` | VARCHAR(100) | 否 | 操作编码，如 `article.approve` |
| `request_uri` | VARCHAR(255) | 否 | 请求路径，只存路径，不含查询参数 |
| `http_method` | VARCHAR(16) | 否 | HTTP 方法，如 `POST` |
| `result` | VARCHAR(16) | 否 | `SUCCESS` 或 `FAILURE`，由 CHECK 约束限制 |
| `duration_ms` | BIGINT UNSIGNED | 否 | 方法执行耗时（毫秒） |
| `created_at` | DATETIME(3) | 否 | 记录时间，默认 `CURRENT_TIMESTAMP(3)`，应用不写入 |

索引与约束：`idx_operation_log_user_time(user_id, created_at)`、`idx_operation_log_time(created_at)`、`fk_operation_log_user`、`chk_operation_log_result`。实体中 `createdAt` 标注 `insertStrategy = NEVER`、`updateStrategy = NEVER`，时间只由数据库生成。

## 3. 查询接口

### 3.1 分页查询 `GET /api/admin/logs`

权限编码 `log:list`。**权限注解尚未接入**：B 的 `@RequirePermission` 合入 dev 后在此 Controller 方法上补 `@RequirePermission("log:list")`，当前既不自建注解也不恒放行。

查询参数（全部可选，条件之间为 AND，省略表示不筛选）：

| 参数 | 类型 | 默认 | 规则 |
| --- | --- | --- | --- |
| `current` | long | 1 | 页码，必须 ≥ 1 |
| `size` | long | 10 | 每页数量，1～100 |
| `userId` | long | 无 | 操作人 ID 精确匹配，必须 ≥ 1；合法但不存在时返回空分页 |
| `operation` | String | 无 | 去首尾空白后精确匹配；空串视为不筛选 |
| `result` | String | 无 | 只接受 `SUCCESS` / `FAILURE` |
| `createdFrom` | LocalDateTime | 无 | 时间起点，**包含**边界，ISO 格式如 `2026-11-08T10:00:00` |
| `createdTo` | LocalDateTime | 无 | 时间终点，**不包含**边界；与 `createdFrom` 同时提供时必须起始 < 结束 |

排序固定 `created_at DESC, id DESC`；无需在请求中传排序字段。越界页返回 `records=[]`，保留真实 `total`。

成功响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [
      {
        "id": "990003",
        "userId": null,
        "userName": null,
        "operation": "article.publish",
        "requestUri": "/api/admin/articles/3/publish",
        "httpMethod": "POST",
        "result": "SUCCESS",
        "durationMs": 15,
        "createdAt": "2026-11-08T11:00:00.000"
      }
    ],
    "total": 1,
    "current": 1,
    "size": 10
  },
  "timestamp": "2026-11-09T05:00:00Z"
}
```

说明：`id`、`userId` 为 JSON 字符串；`createdAt` 为毫秒本地时间，不带时区偏移；外层 `timestamp` 为 UTC。

### 3.2 详情 `GET /api/admin/logs/{id}`

权限编码 `log:read`（同样待 B 的权限注解合入后补充）。路径参数必须是正整数；存在时返回单个 `OperationLogVO`，不存在时 404。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": "990001",
    "userId": "100",
    "userName": "日志演示用户",
    "operation": "article.approve",
    "requestUri": "/api/admin/articles/1/approve",
    "httpMethod": "POST",
    "result": "SUCCESS",
    "durationMs": 12,
    "createdAt": "2026-11-08T10:00:00.000"
  },
  "timestamp": "2026-11-09T05:00:00Z"
}
```

`userName` 通过 `LEFT JOIN sys_user` 取 `real_name`；用户不存在或 `user_id` 为 `NULL` 时为 `null`，不保存历史姓名快照。

### 3.3 错误码与精确提示语

HTTP 状态与外层 `code` 一致，失败时 `data=null`。

| 场景 | HTTP | code | message（当前实现） |
| --- | --- | --- | --- |
| `current < 1` | 400 | 400 | 页码必须大于零 |
| `size < 1` 或 `size > 100` | 400 | 400 | 每页数量必须在 1 到 100 之间 |
| 分页偏移量溢出 | 400 | 400 | 分页偏移量超出范围 |
| `userId < 1` | 400 | 400 | 用户 ID 必须大于零 |
| `result` 非 `SUCCESS`/`FAILURE` | 400 | 400 | 结果只能是 SUCCESS 或 FAILURE |
| `createdFrom >= createdTo` | 400 | 400 | 起始时间必须早于结束时间 |
| 时间/数字参数格式非法 | 400 | 400 | 请求参数错误 |
| 详情 `id <= 0` | 400 | 400 | 日志 ID 必须大于零 |
| 详情记录不存在 | 404 | 404 | 日志不存在 |

分页/详情查询本身只读，不写审计日志。

## 4. 审计切面

### 4.1 使用方式

在需要留痕的写接口方法上添加 `@AuditLog`，`operation` 取自 OpenAPI 的 `x-audit-operation`，不得自造名称或翻译：

```java
@PostMapping("/api/admin/articles/{id}/approve")
@RequirePermission("article:approve")
@AuditLog(operation = "article.approve")
public ApiResponse<ArticleState> approve(@PathVariable Long id, @RequestBody ApprovalRequest request) {
    return ApiResponse.success(articleWorkflowService.approve(id, request));
}
```

D 相关的操作名（来自 `docs/api/enterprise-cms.openapi.json`）：

| 接口 | operation |
| --- | --- |
| `POST /api/admin/articles/{id}/approve` | `article.approve` |
| `POST /api/admin/articles/{id}/reject` | `article.reject` |
| `POST /api/admin/articles/{id}/publish` | `article.publish` |
| `POST /api/admin/articles/{id}/offline` | `article.offline` |
| `POST /api/admin/articles/batch/publish` | `article.publish-batch` |
| `POST /api/admin/articles/batch/offline` | `article.offline-batch` |
| `PUT /api/admin/articles/{id}/tags` | `article.bind-tag` |

其他模块的写接口（用户/部门/角色/权限/分类/标签/文章创建保存提交等）由对应负责人添加，操作名同样以上表来源为准。

### 4.2 记录内容

| 字段 | 来源 |
| --- | --- |
| `operation` | 注解 `operation()` |
| `requestUri` | `HttpServletRequest.getRequestURI()`，不含查询参数 |
| `httpMethod` | `HttpServletRequest.getMethod()` |
| `result` | 方法正常返回为 `SUCCESS`，抛异常为 `FAILURE` |
| `durationMs` | `System.nanoTime()` 差值，转毫秒 |
| `userId` | 当前为 `null`，待 A 的 `CurrentUserProvider` 合入后接入（见第 7 节） |

没有请求上下文（非 Web 调用）时 `requestUri`、`httpMethod` 写空串 `""`。

### 4.3 事务语义

| 场景 | 写入时机 | 写入方式 |
| --- | --- | --- |
| 方法正常返回，且当前存在事务同步 | `afterCommit` | 加入提交后的新连接写入，保证回滚不留下 SUCCESS |
| 方法正常返回，无事务 | 立即 | 直接写 |
| 方法抛异常，事务回滚 | `afterCompletion` 检测到非提交状态 | `writeInNewTransaction`（`REQUIRES_NEW`），失败日志不随业务回滚 |
| 方法抛异常，事务仍提交 | `afterCompletion` 检测到已提交 | 直接写 SUCCESS |

补充约定：原业务异常原样抛出，由公共异常处理生成响应，审计不吞异常；写日志自身失败只记录 `log.error`，不影响业务结果；切面不做重试。

### 4.4 脱敏边界

切面只采集注解给定的操作名和请求元数据，**不采集请求体、查询参数、请求头、密码、Token、认证头**。登录请求不使用通用参数采集切面（`auth.logout` 仅记录元数据）。审计日志表没有请求体字段，需要排查内容时只能依靠业务表与公共异常日志。

## 5. 与查询接口的关系

写接口调用后可在 `GET /api/admin/logs` 中按 `operation`、`userId`、`result`、时间区间检索。审核历史（`cms_review`）和操作日志（`sys_operation_log`）是两份数据：审核历史记录业务意见与轮次，操作日志记录"谁对哪个路径做了什么、成没成功、耗时多少"，两者不互相替代。

## 8. 组员使用说明

1. 写接口需要留痕时，在 Controller 的**具体方法**上加 `@AuditLog(operation = "...")`，`operation` 必须与 OpenAPI `x-audit-operation` 完全一致，不自行改名、不加前后缀。
2. 只加在产生业务变更的写接口；列表、详情、导出等只读查询不写业务审计日志。
3. 登录请求不使用通用审计切面（密码/Token 不得入库）；退出登录按 OpenAPI 的 `auth.logout` 记录元数据。
4. 不要用 `try/catch` 包住 `@AuditLog` 方法再手动调用 `AuditLogWriter`，切面已处理成功/失败两种结果；手动写入会与切面重复。
5. 写日志失败不阻塞业务，是既有设计；若发现日志缺失，先看应用日志中 `写入操作审计日志失败` 的 error。
6. 需要在业务代码里获取操作人时等 A/B 契约合入，使用 `CurrentUserProvider`、`@RequirePermission`，不要临时解析 Token 或读取请求头。
