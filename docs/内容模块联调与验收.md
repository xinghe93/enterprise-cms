# C 模块联调与验收

本文供团队在共享开发环境验收内容模块使用。业务基线为 `dev@07c7bca`，已包含文章写入 PR #51。C 负责文章、分类、标签字典的后台页面与接口，以及知识门户的分类、标签和文章查询。字段及权限以 [OpenAPI](api/enterprise-cms.openapi.json) 为准，事务和数据范围遵循 [接口与协作约定](<接口与协作约定 V1.0.md>)、[跨模块服务接口](<跨模块服务接口 V1.0.md>)。

## 已接入的依赖与事务

| 负责人 | 当前接入方式 |
| --- | --- |
| A | `CurrentUserProvider` 提供经过认证的请求身份。新文章作者由服务端取得。 |
| B | Controller 使用 `@RequirePermission`。文章业务服务再次校验有效权限及作者范围，SQL 在分页计数前应用读取范围。 |
| C | `ArticleAccessService` 和 `ArticleWorkflowService` 已有 `ArticleLifecycle` 实现，供 D 在业务事务内调用。 |
| D | `ArticleTagService` 已接入标签替换和批量读取。成功审计由 `AuditLogAspect` 随业务事务提交。 |

分类、标签和文章写入口使用事务服务开启事务，再通过独立审计 Bean 调用业务服务。文章创建或保存依次完成主表写入、标签替换和详情读取，任一环节失败整体回滚。保存和提交只递增一次版本。分页后一次读取本页标签，空页跳过标签查询。

## 本地验证与页面

1. 按 [四人协作开发指南](<四人协作开发指南 V1.0.md>) 准备开发环境。数据库结构使用 `database/001_init.sql`，权限基线使用 `database/002_seed_permission_baseline.sql`。账号由负责身份模块的成员提供，按相应初始化脚本说明准备。
2. 在 `backend` 目录运行 `./mvnw clean verify`。
3. 在 `frontend` 目录运行 `npm test` 和 `npm run build`。
4. 真实 MySQL 的现有内容测试使用专用空库，先导入 `001_init.sql` 并配置 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD`，再执行 `./mvnw -Dtest=ContentMysqlIT test`。该测试的数据写入随测试事务回滚。普通构建不自动运行这组用例。
5. 页面验收检查 `/admin/categories` 的分类和标签页签、`/admin/articles`、新建与编辑页、文章详情、`/portal` 及门户详情。直接访问和刷新路由也应能正常使用。

后端测试、前端单元测试和构建的成功记录不代表已完成浏览器交互验收。团队应使用编辑账号实际操作页面，再用普通员工账号确认后台拒绝和门户读取行为。

## Apifox 准备

将 `docs/api/enterprise-cms.openapi.json` 导入团队共享 Apifox 项目，并记录导入版本。配置 `baseUrl`，通过 `POST /api/auth/login` 分别取得两个编辑账号、审核员和普通员工的 Token，保存为本地环境变量。真实密码和 Token 不放入导出文件或仓库。

执行下表时保存服务器返回的分类、标签和文章 ID，以及每次写入响应中的最新 `version`。业务 ID 保持字符串形式。文章版本为非负整数，创建后为 0。

创建文章可以省略 `summary` 和 `tagIds`，分别取 `null` 和 `[]`。显式 `tagIds: null` 返回 400。完整保存必须包含 `summary`（允许 null）、`tagIds` 和 `version`。分类完整更新必须包含 `parentId`，根分类显式传 null。

## Apifox 场景

每组先执行正常场景，再核对错误和权限场景。错误响应的 HTTP 状态与 `code` 一致，`data` 为 null。

| 编号 | 场景与操作 | 预期 |
| --- | --- | --- |
| C-01 | 编辑创建根分类及子分类，查询后台树 | 200，字符串 ID，根 parentId 为 null，各层按 sortOrder、id 升序，children 为数组 |
| C-02 | 修改子分类名称和排序，再将根分类移动到子分类下 | 正常修改 200，形成循环的修改 409，重新读取树结构正常 |
| C-03 | 停用父分类，新文章选择其子分类 | 停用 200，创建文章 409；启停不级联子分类 |
| C-04 | 删除有子分类的根节点，随后删除测试空子分类和根节点 | 被引用节点 409，空节点删除 200 |
| C-05 | 普通员工查询后台分类，编辑创建时传未知 status 字段 | 分别 403、400 |
| C-06 | 编辑创建标签、改名、按 keyword 分页、停用并删除未绑定标签 | 各操作 200，名称规范化、返回字符串 ID，分页包含 records、total、current、size |
| C-07 | 重复创建同名标签，删除已绑定标签 | 均 409，原标签与文章绑定保留 |
| C-08 | 普通员工访问后台标签，编辑传数字 tagName 或 status 为 2 | 分别 403、400 |
| C-09 | 编辑用有效分类和标签创建草稿 | 200，作者为当前编辑，DRAFT，version 为 0，publishedAt 为 null，返回完整正文和标签 |
| C-10 | 完整保存时传 summary 为 null、tagIds 为空数组 | 200，摘要和标签被清空，版本只增加一次 |
| C-11 | 保存时传一个不存在的标签 ID；再尝试新增绑定停用标签 | 分别 404、409；每次失败后读取，原正文、标签和版本均保持 |
| C-12 | 分类祖先、标签、作者和包含 %_! 的关键词组合检索 | 200，条件使用 AND，分类包含后代，特殊字符按字面匹配，分页结果含作者和分类名称，列表没有 content |
| C-13 | 第二个编辑读取或保存第一个编辑的草稿，普通员工访问后台文章 | 403，数据不变；authorId 筛选不能扩大当前用户读取范围 |
| C-14 | 提交草稿后，重复用旧版本提交 | 首次 200，变为 PENDING_REVIEW、version 增加一次；旧版本返回 409 |
| C-15 | 删除另建草稿，query 携带 version=0；再次读取详情 | 删除 200、data 为 null；详情 404，数据库 is_deleted 为 1 |
| C-16 | 删除后尝试删除仍被该逻辑删除文章引用的分类 | 409，历史引用仍受外键保护 |
| C-17 | 草稿门户详情、已发布且 visibility=ALL 的门户列表和详情、下架后再次读取 | 草稿 404；发布后 200；下架后详情 404，列表不再包含该文章 |
| C-18 | 门户分类树和标签分页，分别在无可读文章、存在已发布文章、文章下架后读取 | 只包含当前有可读文章的启用选项，无可读文章时为空集合或空分页 |
| C-19 | 无 Token；非法字符串 ID；size=101；重复查询参数；完整保存省略 summary 或 tagIds；正文只有空白 | 分别 401 或 400，不发生业务写入 |
| C-20 | 查询测试库中的 sys_operation_log，按请求路径和 article/category/tag 操作名核对 | 成功业务有 SUCCESS；已授权业务执行失败有 FAILURE；无正文、密码、Token 或完整参数 |

## 真实库的失败原子性验证

在专用测试实例执行，记录目标文章的正文、版本、标签集合和审计条数作为基线。

- 保存文章时新增绑定停用标签应返回 409。再次读取主表和关联，确认本次正文与版本变更一起回滚。
- 使用旧版本提交审核应返回 409，文章状态及版本不变，审计记录 FAILURE。
- 模拟成功审计插入失败时，创建文章应返回 500，主表与标签关联没有本次新增数据。
- 成功删除采用逻辑删除，保留历史引用。已有文章引用的分类和已绑定的标签仍无法物理删除。

审计故障注入涉及数据库配置，应在独立测试实例执行。团队共享开发库通过正常接口验证业务路径。
